# 계정세팅

한 번 돌리면 `계정/<핸들>/`이 채워지고 `/릴스레퍼런스기획`을 쓸 수 있게 된다. 다시 돌리면 갱신이다(기존 문서를 읽고 더하되, 사용자가 직접 고친 줄은 남긴다).
말투: 존댓말, 호칭 없음. 사용자에게 명령어·파일 편집을 시키지 않는다.
폴더: 현재 작업 폴더에서 위로 올라가 `data/refs.json`이 있는 폴더가 수집기 폴더다. `계정/`은 거기 안. 못 찾으면 "수집기 폴더(시작.command 가 있는 폴더)에서 열어주세요"라고 안내하고 멈춘다.

## 원칙 (전 단계)

- 모든 주장에 출처 번호(M-### 내 릴스, R-### 레퍼런스). 출처를 붙일 수 없는 문장은 문서에 넣지 않는다
- 숫자(빈도·길이·비율)는 `.claude/skills/계정세팅/lib/measure.py`가 낸 것만 쓴다. Claude가 어림한 숫자를 쓰지 않는다
- 원문 인용은 대본·캡션 그대로. 다듬거나 지어내지 않는다. 대본은 음성 자동 전사라 오인식이 있을 수 있으니 캡션과 교차해 확인된 구절만 인용한다
- 문서 양식은 `계정/_template/`의 절 구조와 "채우는 법" 지시를 그대로 따른다. 절을 빼거나 새로 만들지 않는다
- 재료가 적으면 적다고 쓴다("대표대본 7건 기준"). 늘려 쓰지 않는다
- 데이터는 `bash .claude/skills/릴스레퍼런스기획/lib/fetch.sh …`로만 읽는다

## 0. 준비

1. `bash .claude/skills/릴스레퍼런스기획/lib/fetch.sh mode` — 수집기 폴더를 찾았는지
2. `fetch.sh ctx` — 핸들·팔로워·평균 조회·대본이 있는 내 릴스 수·브리프·기둥. 핸들이 "(설정 안 됨)"이면 "수집기 경쟁사 탭 오른쪽 위에서 내 계정을 넣고 수집을 한 번 돌린 뒤 다시 불러주세요"라고 안내하고 멈춘다
3. 대본이 있는 내 릴스가 0이면: "내 릴스 대본이 아직 없어요. 수집기 설정 탭에서 '내 계정 상위 N개 릴스의 대본도 수집'을 켜고 수집 시작을 누른 뒤(N크레딧, 한 번만) '됐어요'라고 해주세요." 사용자가 "그냥 캡션으로 해줘"라고 하면 캡션만으로 진행하되 문서마다 "대본 없이 캡션 기준"이라고 적는다
4. `계정/`에 `_template` 말고 폴더가 있으면 그것. 없으면 `계정/_template/`를 `계정/<핸들>/`로 복사
5. 사용자에게 한 줄: "본인 릴스를 재료로 문서 5개를 만들게요. 10분쯤 걸리고, 중간에 세 번 확인을 부탁드릴 거예요."

## 1. 대표대본 모으기

기준선: 내 릴스가 40건 이상이면 조회 상위 20건, 그 미만이면 상위 절반(최소 5건). 대본이 있는 릴스가 그보다 적으면 대본 있는 것 전부 + 나머지는 캡션만. 사용자가 다른 기준을 말하면 그것.

- `fetch.sh my_top <건수>` (또는 `fetch.sh my_top <기준조회수>`)로 받는다. 각 건의 M 번호·조회·캡션·대본이 온다. 첫 3초는 대본 첫 두 문장으로 갈음한다(수집기는 내 릴스의 시각분석을 하지 않는다)

파일 만들기: `계정/<핸들>/대표대본/_index.md`의 "파일 형식" 그대로 `M-###_조회수_캡션첫줄20자.md`. M 번호는 fetch.sh가 준 번호(조회 높은 순). 표(`_index.md`)를 채운다 — 기둥은 비움(수집기는 릴스별 기둥 분류를 하지 않음), 수익유형은 캡션의 공구·광고 표식(#공구·#공동구매·#특가·#마감·#광고·#협찬·#내돈내산)으로 공구/광고/일반.

검증: 파일 수 = 기준선 건수, 각 파일에 `## 대본`·`## 캡션` 절이 있다. 대본이 빈 파일은 `## 대본` 절을 비워 두고, 머리 인용줄에 `> 대본 없음(무음 또는 미추출)`을 적는다 — 절 안에 쓰면 measure.py가 그 표시를 문장·어미로 센다.

## 2. 재기

`python3 .claude/skills/계정세팅/lib/measure.py 계정/<핸들>/대표대본 > /tmp/measure.json` 후 읽는다. 이 JSON의 숫자만 문서에 쓴다.
훅 재료: `fetch.sh refs ""` — 레퍼런스 조회 상위 30건의 대본 첫 두 문장과 `[첫 3초]`(시각분석)·`[후킹]`(종합분석)이 온다. 분석 전 카드는 대본 첫 두 문장만 있다.

## 3. 문서 5개 쓰기 (이 순서로, 하나 쓰고 다음)

### 프로필.md
- 정체성: `fetch.sh ctx`의 브리프(수집기 설정 > 내 채널 정체성)를 원문 인용. 비어 있으면 "수집기 설정 탭의 🪄 자동 분석으로 초안을 받아 저장한 뒤 다시 불러주세요"라고 안내하고, 사용자가 "그냥 진행"이라고 하면 "이 채널을 한 문단으로 소개하면?"을 받아 그대로
- 정체성이 대본에서 발화된 구간: 대표대본 중 채널 정체를 말하는 문장 1~2개 (M-###)
- 타겟: 브리프에서 뽑거나 사용자에게 묻는다
- 점검 기준: 템플릿 문구 유지 + 이 계정 고유 가치 메시지가 있으면 한 줄(대본 근거). 단 `[타겟]` 자리는 이 계정의 타겟 문구로 바꾼다
- 기둥 표: `ctx`의 콘텐츠 기둥을 행으로 두되 건수·배율 칸은 비우고 "릴스별 기둥 분류 없음 — 기둥 이름만 수집기 설정에서" 한 줄
- 규모: 릴스 수·평균 조회·팔로워·대표대본 기준선·최고 조회(M-###)·평균 문장 길이(measure)
- 수익 구조: 캡션 공구 표식 비율(measure.caption.commerce_marked), 대표대본 중 공구 비율, 실제 판매 채널 문구 인용

### DNA.md
- 1절: measure.first_person·calls 빈도 + 원문 예 각 1~2개(M-###). 대본과 캡션에서 호칭이 다르면 둘 다
- 2절: measure.endings_top15 중 상위 10을 표로. 1위 어미가 2위의 2배 이상이면 "이 계정의 서명"으로 적고, 한 대본에 몇 번 나오는지(파일별로 세어) 분량 규칙을 쓴다 — 연속 문단 끝 어미를 같게 두지 않는다는 규칙은 템플릿 문구 유지
- 3절: measure.words_top40에서 주제·행동 / 지시어·연결어 / 감정·평가 / 관계 어휘로 나눠 표. 각 행에 원문 한 구절(M-###). 빈도 2 이하는 넣지 않는다
- 4절: avg_sentence_len, 첫 두 문장 길이 대 해설 구간 길이(per_file.first_two 대비 본문), 상황극·질문-자답·조건절-처방 중 실제로 있는 것만 원문 예와 함께
- 5절: 조회 상위 4건의 시작(first_two)·중간·끝(last) 원문 → 공통점 두세 문장
- 6절: per_file.last를 유형별로 묶어(안내로 닫기 / 실행 지시 / 농담·자조 / 요청) 원문 예. forbidden의 저장·팔로우·댓글 빈도를 반드시 적는다
- 7절: measure.caption 표 + sample_first_lines 5개 원문
- 8절: forbidden 표 전체. 빈도 0은 "쓰지 않는다", 1~2는 "가끔", 그 이상은 원문 자리 예시

### 형식.md
- 대표대본을 구조가 같은 것끼리 묶는다. 묶음 기준은 첫 문장의 종류(고백·대사·실험·상황·조건절·음원·자막 진행·문제 제시)와 중간의 전개(검증·대사·근거·항목·소절·단계)와 마무리(안내·지시·농담). 한 파일은 한 형식에만
- 2건 이상인 묶음만 F번호. 1건짜리는 문서 끝 "## 사례 (형식 미성립)" 절에 M-###만 나열
- 각 형식: 구조(0~3초/~15초/~40초/마무리 — 대본 문장 순서에서, 추정 초 금지), 해당 대표대본과 조회, 중앙 조회, 대본 길이(per_file.chars_no_space 최소~최대, 발화 중심인지 자막 중심인지), 궁합 훅(4번째 문서에서 매긴 H번호 — 훅.md를 먼저 쓴 뒤 채운다), 촬영 난이도(가족 목소리·소품이 대본에 보이면), 원문 예 2~4개
- 중앙 조회 요약 표를 맨 위에

### 훅.md
- 본인 첫 두 문장(per_file.first_two)과 레퍼런스 상위 30건 첫 두 문장·`[첫 3초]`·`[후킹]`을 같은 여는 방식끼리 묶는다. 예시 이름: 손해·후회 고백 / 대사 난입 / 반전 정체 공개 / 눈으로 먼저 보여주는 대비 / 조건절 지목 / 상식 뒤집기·근거 인용 / 음원·리듬 오프닝 — 이 이름을 그대로 쓰지 말고, 이 계정 재료에 실제로 있는 묶음만 이름 붙인다. 최대 7개
- 각 훅: 공식·작동 원리·본인 예(M-###, 조회)·레퍼런스 예(R-###, @계정, 조회) 원문·궁합 형식
- "유형에 넣지 않은 것": 정보 예고형("~알려드릴게요", "~N개")은 레퍼런스에 많아도 본인 forbidden 빈도가 0이면 안티패턴으로 분류
- 레퍼런스가 없으면 레퍼런스 예 자리에 "본인 예만"이라고 쓰고, 본인 예 1건짜리 훅은 만들지 않는다

### 안티패턴.md
- A절: 템플릿 4줄 유지 + 사용자에게 묻는다(4단계 검토에서)
- B절: 수집기는 내 릴스 코칭을 하지 않으므로 "코칭 데이터 없음" 한 줄만. 대신 대표대본 중 조회 하위 건과 상위 건의 첫 두 문장을 비교해 눈에 띄는 차이가 있으면 원문 인용으로 한두 줄(M-###)
- C절: 비워 둔다(형식 안내만)

### 공구광고.md
- 대표대본 중 수익유형 공구·광고가 2건 이상일 때만 채운다: 3단 배치 표에 원문, 구매 안내 위치 실측(대사에 안내가 든 건수와 위치, 가격·기간이 대사에 든 건수), 캡션 표식 위치, 공구 선례 표(형식별), 상위권 공구·일반 중앙 조회 비교
- 1건 이하면 문서 머리에 "공구 선례 없음 — 공구·광고 모드에서는 선례 없음으로 안내" 한 줄만 두고 표는 비운다

## 4. 사용자 검토 (하나씩, 답을 받고 다음. 처음 쓰는 사람 기준으로 — 질문마다 예시와 답하는 법을 붙인다)

세 질문 모두 아래 틀을 지킨다: 무엇을 보여주는지 한 줄 → 표나 목록 → 질문 → "예를 들면" 두세 개 → 답하는 법(그대로 칠 수 있는 예시 답 하나 + "없으면 '없어요'"). 전문 용어(DNA·안티패턴·어미) 대신 풀어 쓴다.

1. `대표대본/_index.md` 표(번호 · 조회수 · 첫 줄 · 유형)를 보여주고:
   "이건 앞으로 대본을 쓸 때 '내 말투 견본'으로 삼을 릴스 목록이에요. 이 중에 **'이건 내 스타일이 아닌데'** 싶은 게 있나요? 예를 들면 광고주가 준 대본을 그대로 읽은 것, 예전에 다른 방향으로 운영할 때 올린 것, 다른 사람이 대신 찍어 준 것, 그냥 실험 삼아 올린 것이요. 있으면 번호로 말해주세요 — 이렇게요: `M-012 빼줘`. 없으면 `없어요`라고 해주세요."
   → 뺀 파일은 이름 앞에 `제외_`를 붙이고, measure를 다시 돌려 DNA 2절·8절 숫자를 갱신. "이 릴스는 왜 잘 됐나요?" 같은 질문이 오면 표의 조회수만 근거로 짧게 답하고 다시 질문으로 돌아온다
2. DNA.md 8절(쓰지 않는 것)의 현재 표를 보여주고:
   "대본에서 지금까지 한 번도 안 쓴 표현들을 재서 뽑았어요. 여기에 **'나는 이런 말 절대 안 써'** 하는 걸 더 넣을까요? 예를 들면 '여러분' 같은 호칭, '~하시길 바랍니다' 같은 딱딱한 말투, 반말, 특정 유행어나 이모지요. 있으면 적어주세요 — 이렇게요: `'여러분'이라는 말은 안 써요, 반말도 안 써요`. 없으면 `없어요`."
   → 적은 것은 8절 표 아래 "운영자가 직접 추가" 줄로 원문 그대로 넣는다
3. 안티패턴.md A절(운영자 지정 금지 목록)의 현재 줄을 보여주고:
   "앞으로 기획할 때 **'이건 하지 마'** 하고 못 박을 게 있나요? 예를 들면 정치·종교 얘기, 특정 경쟁사 이름 언급, 아이나 가족 얼굴 노출, 자극적인 낚시 훅, 특정 제품·브랜드 언급, 촬영이 어려운 장면(야외·여러 사람)이요. 있으면 적어주세요 — 이렇게요: `아이 얼굴은 안 나오게, 경쟁사 이름은 언급 안 해요`. 없으면 `없어요`."
   → 적은 것은 A절에 "무엇 · 왜(사용자 말 그대로) · 대신 어떻게(비움)" 형식으로 추가. 기본 4줄이 이 계정 데이터와 충돌하면(예: 금지 표현이 실제 상위 릴스를 열었음) 그 근거(M-###, 조회수)를 보여주고 빼거나 바꿀지 함께 묻는다

## 5. 마무리 보고

한 화면으로: 만든 파일 수, 대표대본 N건 기준(대본 있음 N건), 서명 어미와 빈도, 형식 N개·훅 N개, 비워 둔 곳과 이유(예: 기둥 분류 없음·코칭 없음·공구 선례 없음), 그리고 "이제 'R-001로 기획해줘'처럼 카드 번호로 부르면 이 문서로 기획을 시작해요."

## 다시 돌릴 때 ("프로필 다시 만들어줘", 대표대본이 늘었을 때)

- 기존 문서를 먼저 읽는다. 사용자가 직접 고친 줄(A절, DNA 8절 추가, C절)은 그대로 둔다
- measure를 다시 돌려 숫자를 교체하고, 새 대표대본이 있으면 형식·훅에 인용을 덧붙인다(조회가 낮은 인용을 밀어낸다)
- 무엇이 바뀌었는지 한 줄 보고

## 하지 않는 것

- 출처 없는 문장, 어림한 숫자, 다듬은 인용
- 재료가 적은데 문서를 채우기 위해 일반론을 쓰는 것 — 빈 칸은 "재료 없음"이 맞다
- `.claude/` 안의 양식·패턴 문서 수정
